Flash from Linux (Fedora / any distro)

The CLI works with Python 3 only, no root, and resolves the latest release for you.

tools/flash/openmesh-flash
# list supported boards and USB ids
./tools/flash/openmesh-flash --list

# detect the board and flash it (UF2 copy for nRF52, esptool for ESP32-S3)
./tools/flash/openmesh-flash --board auto

# dry run first: verify the download and print what would happen
./tools/flash/openmesh-flash --board t1000e --dry-run

Fedora udev + dialout

sudo usermod -aG dialout "$USER"
# log out and back in, then:
ls -l /dev/ttyACM*
# nRF52 UF2 drives mount automatically; no udev rule needed
./tools/flash/openmesh-flash --list

ESP32-S3 permissions

# if /dev/ttyACM0 is missing after plugging in:
sudo dnf install -y esp-idf  # provides esptool (or: pip install esptool)

Before you flash

1. Back up nothing, lose nothing

Flashing replaces the factory firmware. Your OpenMesh identity seed is generated on first boot and stored encrypted in flash; flashing again erases it. Copy messages and settings you care about before switching.

2. Antenna first

Never transmit without an antenna attached — the SX1262/LR1110 power amplifier can be damaged. Use the correct band for your region (EU868, US915, AU915 or AS923).

3. After flashing

Open the OpenMesh web client or bridge, connect over USB/BLE, and the radio appears as a companion device. Repeaters run standalone: no app required after one USB configuration pass.

OpenMesh is AGPL-3.0-or-later · hardware docs: docs/hardware/boards.md · firmware docs: firmware/README.md

WebSerial flashing uses esp-web-tools. UF2 files are copied by your operating system's mass-storage driver — this page never touches a serial port for nRF52 boards.
